# 8 GB 显存档：配方与读数（2026-10-22）

> 证据等级：标 `A` 的都是本机实测、至少跑两臂。机：RTX 4080 SUPER **32760 MiB** / i7-13790F（8P+8E）/ 96 GiB DDR4-2667 / Windows。
> 引擎：**PolyStrata 0.1.44.1 的 `strata-poly`**，与 32GB 精确线**同一个 exe、零改码**。
> 本文只写 8GB 档；32GB 精确线见 `README-精确线.md`。

---

## 1. 一句话

用 `--vram-reserve-mib 24568` 把 32760 MiB 的卡压成 **8192 MiB 档**，专家留在系统内存、
按画像排序的专家缓存上卡、没命中的就地交给 CPU 池算。**2K prompt decode 58.35 tok/s（带 profile 68.23），prefill 1918.3。**

## 2. 读数（A）

| 项 | 读数 | 对照 32GB 全常驻 |
|---|---|---|
| **prefill 2K** | **1918.3 tok/s** | — |
| **decode 2K，无 profile** | **58.35 tok/s** | — |
| **decode 2K，带 profile** | **68.23 tok/s** | — |
| **prefill 8K** | **3388.2 tok/s** | 3478.1（**差 2.6%**） |
| 专家驻留 | **2396 / 10240 = 4.3 GiB** | 10240 / 18.7 GiB |
| 命中率 | 67.2% → **74.5%**（profile） | 100% |
| CPU 专家（长 prompt） | 0.6 ms/token | 0.0 |
| CPU 专家（10–34 token 短问） | **11–14 ms/token** | 0.0 |
| 短问 decode | **41–56 tok/s** | 175–177 |
| pin-arena 搬运 | 23,532 次 / **13.91 GB**（≈13.2 GB/s） | 0 |
| 加载 | 9.6 s（冷）/ 2.2 s（热） | 7.2 s |

## 3. 配方（可直接跑）

```powershell
$env:PATH = "<CUDA 13.3>\bin;<CUDA 13.3>\bin\x64;<repo>\PolyStrata\build-p3;" + $env:PATH
$env:STRATA_PIN_ARENA_GIB = '20'          # ← 唯一决定性开关

& '<repo>\PolyStrata\build-p3\strata-poly.exe' `
  --model '<模型目录>\Sage-A1.5-Q4_K_M.gguf' `
  --vram-reserve-mib 24568 `               # 32760 − 24568 = 8192 MiB ⇒ 就是 8GB 档
  --max-context 12288 `
  --window 1 --lookup 0 `
  --expert-profile '<repo>\profile\sage-profile-2k.bin' `
  --tokens-file '<ids 文件>' `
  --max-new 128
```

或者用 `scripts\run-8g.ps1 <log-tag>`（改开头几行路径）。

**依赖**：exe 的导入表要 **`cublas64_13.dll`** = **CUDA 13.3**。12.x 会 `0xC0000135`。

## 4. 逐参数

| 开关 | 取值 | 为什么 |
|---|---|---|
| `STRATA_PIN_ARENA_GIB` | **20** | 把专家银行钉成一个 arena，miss 走 zero-copy DMA。**不设：prefill 939 vs 1918（差一倍）** |
| `--vram-reserve-mib` | **24568** | `卡总 − 8192`。引擎自己会打印它选了什麼（`expert cache auto: … -> N slots`）—— **只信那行** |
| `--max-context` | **12288** | 必须 > `prompt + max-new`，否则报 `the prompt and --max-new together exceed --max-context`。8K prompt 至少 12288 |
| `--window 1` `--lookup 0` | 关投机 | 草稿头吃 **124–125 个专家槽**，多行验证 12.0–26.3 ms/轮 vs 7.5 ms 基线。8GB 上槽最贵 |
| `--expert-profile` | `profile/sage-profile-2k.bin` | 按路由频率排缓存：**decode +16.9%，命中 67.2% → 74.5%** |
| `--max-new` | **≥128** | Sage 是推理模型，`<think>` 经常吃掉 64 token 还没出答案，给小了会误判成"答不出来" |
| `--threads` | 先留默认 | 本机默认用满可用线程；**超过物理核是悬崖**（见坑表 §5），值得单独对一臂 |

**不要用**：`--kv-resident`（静默丢上下文）、`--pcie-frac`（噪声带内，1.0 更差）、
`--expert-cache-per-layer`（树内自报 decoded 21% slower）、`--prompt-batch` < 1024（输出本身会变）。

## 5. 换一张卡怎么算

```
--vram-reserve-mib = 卡总 MiB − 8192
STRATA_PIN_ARENA_GIB ≈ 专家银行 GiB（本模型 18.7 ⇒ 20）
```

⚠️ **reserve 是从「空闲显存」扣的，不是从卡总扣。** 本机桌面占 1.1 GiB，引擎算的是
`28805 − 24568 = 4237 MiB ≈ 4.14 GiB` 的专家缓存。**换档位之间别动桌面**，否则档位会悄悄漂。

## 6. 质量验收：9 题问答

题库：常识 + 算术 + 应用题，答案确定。同 ids 分别在 8GB 档与 32GB 全常驻跑，**逐 token 比**。

| # | 问题 | 8GB 档 | 32GB 全常驻 | 逐 token |
|---|---|---|---|---|
| 01 | 中国首都 | `<think>` 中 | 同 | **前 64 逐位相同** |
| 02 | 一年几季 | 一年有四个季节，春、夏、秋、冬 ✅ | 一模一样 | **前 64 逐位相同** |
| 03 | 水沸点 | `<think>` 中 | 同 | 第 57 位翻转 |
| 04 | 光速 | 每秒 299,792,458 米 ✅ | 一模一样 | **前 64 逐位相同** |
| 05 | 三角形内角和 | 180 度 ✅ | 一模一样 | **前 64 逐位相同** |
| 06 | 8×5 面积周长 | 40 平方厘米 / 26 厘米 ✅ | 一模一样 | **前 64 逐位相同** |
| 07 | 3^7 | 2187 ✅ | 2187 ✅ | 第 15 位翻转 |
| 08 | 1 加到 100 | 5050 ✅ | 5050 ✅ | **前 64 逐位相同** |
| 09 | 200×0.8×1.13 | `<think>` 中 | 同 | **前 64 逐位相同** |

**7/9 前 64 token 逐位相同；6/9 直接答对。智力没有损失。**

两个必须记住的：
1. **自我问答复读不是流式的锅**——32GB 全常驻档逐字复现（成因是 `问：…答：` 这个 prompt 形状）。
2. **`<think>` 模式下 64 token 不够**——全常驻档 128 token 也还在想。别只看尾巴就判"答不出来"。

另：8-token prompt 时，8GB 档前 **32 个生成 token** 与全常驻档**逐位相同**（都从 `271,248068,198,8160,…` 起）。

## 7. 边界（发货时要一起说）

| 项 | 状态 |
|---|---|
| **物理 8GB 卡实跑** | ❌ **没试**。本档是用预算在 32760 MiB 卡上压出来的；算术可外推，驱动的真实行为不一定 |
| `--kv-resident` | ❌ **必须关**（静默 mask KV cell ⇒ 丢上下文） |
| `--serve` / API | ⚠️ 本档只用 CLI 测过，serve 路径未测 |
| 视觉（mmproj） | ❌ 未用；8GB 的显存留给专家缓存更值 |
| 多卡 | ❌ 未测 |
| 架构 | exe 带 `sm_89` 机器码（CUDA 13.3），换卡要重编 |
