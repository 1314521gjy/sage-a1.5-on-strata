# 诊断：Sage Agent 思考循环（2026-10-21）

## 症状

DSH 里 Sage 反复输出：
`I'll give them clear instructions... Actually, I should load the role-lead skill first... Let me spawn the team... Actually, I'll just proceed...`
一直不调用工具/不结束。

## 证据

- 256K 服务日志（`E:\models\Sage-A1.5\poly\logs\serve-256k-stdout.log`）：
  - 第一条请求：prompt **30,855 tokens**，thinking 18 → answering 188 → `done 260 (stop)`；
  - 第二条请求：thinking **148 → 6,031 tokens**，34 s，**`done 6031 (disconnect, cancel=True)`**，一条答复都没有。
- DSH 请求头（`request/header`）：只有 `provider/model/maxTokens`，**没有 temperature/top_p**。
  ⇒ `serve/server.py:785-786`：**缺 temperature = 引擎默认 = greedy**；`src/poly/main.cpp:83/101`：temp 0 走 `most_likely`。
  ⇒ **不是高温；是贪婪**。
- 35B 模型 metadata 里的 `general.sampling`（temp 1.0/top_p .95/top_k 20）**不是**这条链实际用的采样；PolyStrata 不读它，服务端默认 greedy。

## 旧案

`E:\视频\_flashnext\HANDOFF-20260929b-场景任务判决与官方口径.md:20`：
Q2_0 自修轮“思考塌成死循环”，同一句 `Could be sun.shadow.map? no.` **重复 17 次**，烧 **68,535 token / 20 分钟 / 零产出**，人工杀。
同件 `:50` 的判据：**`/status` 尾部同一句重复 ≥5 次 ⇒ 判死循环，立即停**。
⇒ 这次是同一类：思考重复、无产出；区别是 Sage 这条没有“立即停”的护栏。

## 根因

PolyStrata **自带** `reasoning_loop_recovery`：
- `serve/server.py:7244-7250` 读 config：`false`（默认，关）/ `"stop"` / `"recover"`（true 等价 recover）。
- `serve/server.py:4546-4570`：`parser.state=="reasoning"` 且 `reasoning_repeat_coverage` 超阈值 ⇒ 触发。
- `serve/server.py:4632-4651`：`"recover"` 时把 **temperature 抬到 ≥1.0、presence_penalty 抬到 ≥1.5**，用低 effort 指令续跑；**top_p/top_k 不动**，请求 dict 不被改；**只恢复一次**。
- `serve/test_reasoning_loop_recovery.py` 是它的回归测试（18 项）。

**我们的 `sage-serve-exact-256k.json` 没写这个键** ⇒ 默认 false ⇒ 循环不会被接住，只能等 max_tokens/断连。

## 修复（已做）

`E:\rlab\20-生产\PRJ-SAGE\交付\sage-serve-exact-256k.json` 增加：

```json
"reasoning_loop_recovery": "recover"
```

重启 256K 服务（PID **21464**，engine **20896**，`/health` 200，`n_ctx=262144`）。
CPU 回归：`python -m unittest serve.test_reasoning_loop_recovery -v` ⇒ **Ran 18 tests, OK**；
日志可见 `[strata] repeated reasoning detected at 2048 tokens (coverage=1.000); resuming ...`。

## 判据 / 负控

- 开：同一段重复思考在 ~2048 token 触发 `repeated reasoning detected`，随后 `done`（stop/length）；不触发 ⇒ 没开成。
- 关：`reasoning_loop_recovery` 缺省/ false ⇒ 只跑一遍，无 recovery 行（单测 `test_disabled_is_one_pass`）。
- 请求 dict 不被改：单测 `test_old_explicit_sampler_recovers_without_mutating_request`。
- top_p/top_k 不被改：单测 `test_a_lower_top_p_and_top_k_are_never_raised_or_lowered`。

## 注意

- `"recover"` 会**刻意抬高 temperature**（≥1.0）来打破循环 ⇒ 恢复后的输出**不是** greedy 原轨迹；这是为可用性付的代价。
- `reasoning_budget_tokens` 仍是 **0（无上限）**；1+1 那种“纯想不答”不属于重复循环，不会被 recovery 接住，仍会烧到 max_tokens。要它也停，需设预算。
- 并发仍是 FIFO（poly 无 batch），与本次循环无关。
